# 掲示板の軽量化・切替基準

この文書は、掲示板を「軽い・分かりやすい・一部が失敗しても使える」状態に保つための恒久実装基準です。月替わりやUI改修でも、ここにある契約を明示的な仕様変更なしに後退させません。

## 画面を軽く保つ目標

- 動画一覧は、画面外の全動画を一括先読みしない。実動画サムネイルは `IntersectionObserver` で表示領域の少し手前（現在は160px）に入ったカードだけを有効化する。
- 一覧の動画サムネイルは自動再生・controlsなし。該当カードだけ `preload="metadata"` と小さな先頭シークで実フレームを出し、失敗時はファイル名＋「タップして再生」のプレースホルダーへ戻す。
- 動画詳細は最初の動画だけmetadataを先読みし、グループ内の2本目以降はユーザー操作まで待たせる。複数動画が同時に回線を奪わない。
- コメントは1回20件、返信は押した時に取得する。新着確認は可視タブだけで行い、Mutation後に全件再取得・全画面Loading・ページ再読み込みを行わない。
- 画像・サムネイルは表示領域を先に確保してCLSを抑える。動画、翻訳、コメント、投票、統計の失敗境界は分離する。

目安として、実機計測では初回LCP 2.5秒以下、CLS 0.1以下、主要操作のINP 200ms以下を目標とします。数字を満たすために、測定なしの大規模な書き換えや依存ライブラリ追加はしません。

## 動画の保存・投稿・再生

- 動画上限は12 MiB。R2 multipartの最低サイズ制約を守り、5 MiB + 5 MiB + 残りの最大3パートを既存3ワーカーで並列送信する。
- 並列アップロードの進捗は各パートの送信済み量を合算する。通常完了時は不要なR2 HEADを挟まず、重複完了・応答消失時だけ限定的な回復確認を行う。
- 既存の途中アップロードはDBに保存済みの `part_size` を使い、途中セッションを新設定へ強制変換しない。
- 再生は同じR2オブジェクトへのHTTP Rangeで行う。プレイヤーやサムネイルの失敗で掲示板本文・投票・コメントまで消さない。
- 将来専用Thumbnail Workerを導入する場合も、一覧の遅延読込・非自動再生・失敗時プレースホルダーを維持する。

## 月次UIの恒久ルール

- 新キャラ掲示板は毎月同じ導線と密度を保つ。日本語の入口カードは二つ名を省き「名前だけ」を表示し、公式フルネームは照合用データとして保持する。
- PvPトップの掲示板カードはスマホ最優先。ヘッダー境界線の直下へ寄せ、カード・名前・注目コメント・ボタンを読める大きさに保つ。キャラ画像は全身が切れない `object-fit: contain` を維持する。
- キャラ名は最大2行、注目コメント本文は最大2行。長文でカード全体が崩れないことと、文字を小さくし過ぎないことを両立する。
- 過去月のDB掲示板、投稿、投票、評価、既読、権限、監査、R2メディアをUI変更のために削除・再作成しない。
- 新キャラの自動追加は確認済みID・リリース月・公式メタデータの既存ゲートを通し、PvP集計ロジックへ波及させない。

## エラーを広げないルール

- 0件（`success/empty`）とAPI障害（`error/stale`）を別表示にする。障害時に0件へ変換しない。
- Abort・request sequence・有限Retry・Timeoutを維持し、古いレスポンスを最新画面へ適用しない。
- 書き込み障害ではRead-onlyへ縮退し、閲覧と前回正常値を残す。ログには操作名・時間・成功可否・エラー種別だけを記録し、本文や個人情報を保存しない。

## 新キャラの切替基準

月の変更だけでは掲示板を切り替えません。確認済みキャラクターID・画像・JSTリリース月・公式メタデータ・観測ゲートを満たした項目だけを月別掲示板へ追加します。過去月のDB行はそのまま閲覧可能にし、未確認IDを仮名で公開しません。

## 確認コマンド

変更後は次を実行します。

```sh
npm run build
node --test tests/*.test.mjs
```

実機確認では、動画0件・複数動画・Slow 4G・サムネイル失敗fallback・動画再生中のコメント操作・通信切断後の再試行を確認します。
